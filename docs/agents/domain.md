# Domain Docs

This repository uses a single domain context.

## Read before exploring the code

- Read `GLOSSARY.md` at the repository root when it exists.
- Read ADRs in `docs/adr/` that apply to the area under investigation.
- If either location is absent, proceed silently. `/domain-modeling` creates these documents when terms or decisions are resolved.

## Use the agreed vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names. If a term is missing, check whether the project already uses another term; record a real gap for `/domain-modeling`.

## Surface decision conflicts

If a proposal contradicts an ADR, identify the ADR and explain why its decision should be reconsidered.
